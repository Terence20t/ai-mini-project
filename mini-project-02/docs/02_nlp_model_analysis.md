## 1. 검색기 구현 및 임베딩 확인 (CP-02~CP-06, CP-08)

| 검색 방식 | 사용 모델·표현 방식 | 전체 문서 벡터 Shape |
|---|---|---|
| TF-IDF | 문자 2~3-gram, `max_features=30000` | _(200, 30000)__ |
| BERT | `klue/bert-base` + Masked Mean Pooling | _[2, 19, 768]__ |
| Sentence-BERT | `snunlp/KR-SBERT-V40K-klueNLI-augSTS` | _(200, 768)__ |

- **BERT Encoder 출력 / Attention Mask / Pooling 결과 Shape (CP-03~04의 질문 2개):** _[2, 19, 768]__ / _[2, 19]__ / _(2, 768)__
- **BERT와 Sentence-BERT의 최대 입력 길이:** Bert : 512토큰, S-Bert : 256토큰
- **Padding을 평균 계산에서 제외하는 이유:** _Padding 토큰은 문장마다 길이를 맞추기 위해 추가한 빈 자리이며, 실제 문맥 정보가 없습니다. 이를 평균에 포함하면 문장 벡터가 실제 내용과 무관한 패딩 위치의 영향을 받아 달라질 수 있습니다.
그래서 attention_mask가 1인 실제 토큰만 평균에 포함하고, 0인 패딩 토큰은 제외합니다.__
- **BERT와 Sentence-BERT 문서 벡터를 혼합하지 않는 이유:** _두 벡터가 같은 문서를 표현하더라도 학습 방식과 벡터 공간의 의미가 다르기 때문입니다.
- 일반 BERT의 [CLS] 또는 평균 풀링 벡터는 문장 간 유사도 비교에 맞춰 학습된 표현이 아닐 수 있습니다.
- Sentence-BERT는 문장 임베딩과 코사인 유사도 비교에 적합하도록 학습된 모델입니다.
- 두 벡터를 이어 붙이거나 평균 내면 각 공간의 척도와 의미가 섞여, 어느 한쪽의 검색 품질이 오히려 떨어질 수 있습니다.__
- **Pooling·코사인 유사도·검색 결과 검증 셀 실행 결과:** _정답 문서가 상위 5개 중 몇 번째에 나왔는지를 역순위로 평가합니다. 1위면 1, 2위면 1/2, 3위면 1/3이며, 상위 5개에 없으면 0입니다.__

## 2. 검색 평가 기준 (CP-07)

- **평가에 사용하는 검색 결과:** Top-5 문서
- **질문별 지정된 정답 문서 수:** 1개
- **Hit@1이 평가하는 내용:** _첫 번째 검색 결과가 정답 문서인지 평가합니다. 맞으면 1, 아니면 0__
- **Recall@3이 평가하는 내용:** _지정된 정답 문서 1개가 상위 3개 안에 검색되었는지 평가합니다. 정답이 하나이므로 상위 3개에 있으면 1, 없으면 0입니다.__
- **MRR@5가 평가하는 내용:** _정답 문서가 상위 5개 중 몇 번째에 나왔는지를 역순위로 평가합니다. 1위면 1, 2위면 1/2, 3위면 1/3이며, 상위 5개에 없으면 0입니다.__

동일한 검색 방식에서 `final_compare`의 결과를 기록합니다.

| 데이터 | 질문 수 | Hit@1 | Recall@3 | MRR@5 |
|---|---:|---:|---:|---:|
| Validation | 60 | _0.883333 | 0.966667 | 0.916667__ |
| 보류 Test | 20 | _0.800000 | 0.800000 | 0.812500__ |

**해석:** Validation과 Test의 지표 차이를 실제 수치로 비교하고, Test에서 실패한 질문의 특징과 예상 원인을 작성합니다.  
>보류 Test의 Hit@1은 Validation보다 0.083333(약 8.33%p) 낮고, Recall@3은 0.166667(약 16.67%p) 낮으며, MRR@5는 0.104167(약 10.42%p) 낮습니다. Test에서 세 지표가 모두 떨어졌고 특히 정답을 상위 3개 안에 포함하는 비율의 하락이 컸습니다. Validation보다 새로운 질문에서 TF-IDF 검색 성능이 낮게 나타난 것으로 볼 수 있습니다.

>TF-IDF는 질문과 문서의 단어 일치에 크게 의존하므로 표현이 다르거나 동의어·바꿔 쓴 표현이 사용된 질문, 핵심 단어가 드문 질문, 여러 문서가 비슷한 단어를 포함하는 질문에서 정답을 놓쳤을 가능성이 있습니다. 새로 입력한 의료 분야 질문에서도 코퍼스에 관련 내용이 없는 상황에서 낮은 점수의 문서가 Top-3에 표시됐습니다. 따라서 검색 결과 목록만으로 관련 문서가 있다고 판단하지 말고, 점수 기준이나 “관련 문서 없음” 처리를 추가로 검토할 필요가 있습니다.

>새 질문 평가는 기존과 동일한 코퍼스 안에서 질문만 바꾸어 수행했으므로, 새로운 문서가 추가되거나 기존 문서가 변경되는 실제 업무 상황까지 검증한 것은 아니고, Validation 60개, Test 20개로 평가 규모가 작아 지표가 질문 구성에 따라 달라질 수 있다. 질문마다 정답 문서를 하나만 지정했기 때문에, 실제로는 다른 문서도 유효한 답을 제공하는 경우를 충분히 평가하지 못한다.

>실제 업무에 적용하기 전에는 업무에서 실제로 쓰이는 질문과 최신 문서를 포함한 더 큰 평가 데이터를 만들고, 질문별로 복수의 관련 문서를 지정해 평가해야 한다. 검색 실패 사례와 관련 없는 문서가 높은 순위에 나온 사례를 확인하고, 문서 추가·갱신 시 성능이 유지되는지, 관련 문서가 없을 때 이를 구별할 수 있는지도 점검해야 한다.
