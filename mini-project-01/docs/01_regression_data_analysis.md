> - 입력 특성의 최종 **선택 이유**는 `adr.md`에 따로 정리합니다.

## 1. 데이터 탐색 (CP-01)

- **데이터 크기:** 17379 행, 17 열
- **결측값 및 중복 행:** 결측값 없음, 중복 행 없음
- **대여량(`cnt`) 분포의 특징:** 
> - 기초통계량 : 평균 189.46대, 중앙값 142대, 최소 1대, 최대 977대. 
> - 히스토그램 : 적은 대여량에 관측치가 몰리고 큰 값 쪽으로 꼬리가 길다.
- **평균 대여량이 높은 시간대:** 출퇴근시간대(07~09시, 17~19시), 낮시간대(10~16시)

**분석:**
> 시간대별 대여량 그래프에서 08시 및 17~18시에 대여량이 집중되는 패턴을 보이고 있고, 수요가 높은시간대와 낮은 시간대의 차이가 크게나타나 모델의 시간대별 예측오류를 별도로 확인할 필요가 있다.

## 2. 데이터 분할 및 누수 확인 (CP-02)

- **Train:** 2011-01-01 ~ 2012-05-25 / 12139 건 / `cnt` 평균 159.7
- **Validation:** 2012-05-26 ~ 2012-09-12 / 2640 건 / `cnt` 평균 281.4
- **Test:** 2012-09-13 ~ 2012-12-31 / 2600 건 / `cnt` 평균 234.9
- **시간 순서로 분할한 이유:** 시간의 순서가 바뀌면 분석의 결과가 전혀다른 결과로 바뀔수 있음. 같은 날짜의 기록이 서로다른 집합에 석이지 않도록 한다.
- **`casual + registered == cnt` 확인 결과:** 전체 17379건 모두 수식이 성림됨(회원, 비회원 구분)
- **누수 가능성이 있어 제외한 특성과 이유:** casual, registered의 합은 cnt와 동일한 값으로 회원구분은 분석대상에서 제외

**분석:**
> 세 집합의 `cnt` 평균이 서로 다르다면, 그 차이가 이후 모델 평가에 어떤 영향을 줄지 1~2문장으로 작성합니다.  
> 기후와 관련하여 대여건수가 영향이 있을 수 있어, train과 validation의 오차가 크게 나타날 수 있음.

## 3. 상관관계 및 입력 특성 분석 (CP-02)

- **`temp`와 `cnt`의 상관관계:** 0.398  약한 중간정도의 양의 상관관계
- **`hum`과 `cnt`의 상관관계:** -0.301  음의 상관관계
- **`windspeed`와 `cnt`의 상관관계:** 0.094  매우약한 양의 상관관계
- **`temp`와 `atemp`의 상관관계:** 0.992  상관관계가 매우 높고 거의 비슷한 움직임을 보임.
- **사용한 특성 목록(`FEATURES`):**
> - FEATURES = [
    "season",
    "yr",
    "mnth",
    "hr",
    "holiday",
    "weekday",
    "workingday",
    "weathersit",
    "temp",
    "hum",
    "windspeed",
	"is_commute_hour"
]
> - TARGET = "cnt"
  (선택 근거는 `adr.md` 의사결정 ①에 작성)

**분석:**
> 상관계수는 선형 관계만 나타내며 인과관계를 의미하지 않는다. 또한 상관계수가 낮더라도 비선형 관계가 존재할 수 있고, 실제 예측 성능에 도움이 되는 특성일 수도 있다. 따라서 상관계수만으로 특성을 제거하지 않고 모델 학습 및 성능 비교를 통해 최종 특성을 결정해야 한다.

## 4. 특성공학 및 전처리 (CP-03)

- **생성한 특성:** `is_commute_hour`
- **특성 생성 조건:** 근무일이고 출근시간 퇴근시간대이 면 1, 아니면 0
- **범주형 특성 처리:** ['yr', 'season', 'mnth', 'weekday', 'weathersit']
- **수치형 특성 처리:** ['temp', 'atemp', 'hum', 'windspeed', 'hr']
- **이진 특성 처리:** ['holiday', 'workingday', 'is_commute_hour']
- **Train 전처리 전후 Shape:** 변환 전 Train: (12139, 13) → 변환 후: (12139, 37)
- **Validation에 적용한 변환 기준:** 변환 전 Valid: (2640, 13) → 변환 후: (2640, 37)
